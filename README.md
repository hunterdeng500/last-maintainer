# 最后一位维护员 × bug大乱斗

一款中文俯视角像素探索游戏。人类离开之后，小镇仍靠旧系统运转。你背着工具包走过街道，在现场发现六种异常，阅读日志与配置，再决定修复系统，还是利用漏洞。

沿用原作六个技术故障和三种结局，改为可行走的小镇：道路、建筑、树木、水域、区域门禁、昼夜变化与维护手记。本次以 E. M. 福斯特《机器休止》的机器崇拜、二手知识与地表亲历为主题，扩写为中文互动演绎，并非原文翻译。认真调查并阅读可选档案的设计目标约 **25–40 分钟**，并非实测时长；开场可跳过，长文可以关闭，熟悉流程后仍可较快完成。视觉和探索节奏参考《星露谷物语》，像素图形全部由程序原创绘制；本作聚焦 bug 调查与维护抉择，没有务农、恋爱或经营系统。

六处现场分别保留准确的代码成因，并增加对话档案、建造者交接痕迹和选择后的短过场。园丁保存瓦西蒂式的机器信仰，巡检机保存库诺留下的质问与放逐处分，配送机保管逐渐失传的维修知识；它们都是服务机或旧录音，地表没有新增人类居民。随着维护推进，故事从“小毛病自有道理”，走向“谁来修复修补装置”，最后面对机器正在停止的事实。详见 [CHANGELOG-machine-stops.md](CHANGELOG-machine-stops.md)。

小镇现采用 **2.5D 斜俯视**表现：六处建筑分别绘制亮屋顶、南立面与暗侧墙，道路下沉、河岸露出石壁，台阶与桥面体现高度。人物、树木、建筑和道具按脚底位置遮挡，软投影随昼夜变化；维护员带工具包与四向步态，行走有短加速与制动，镜头平滑跟随并略微看向移动方向。全部仍由原生 Canvas 2D 绘制和缓存，零运行依赖；手机横屏会保持角色可辨，系统“减少动态效果”设置可关闭环境微动与冲刺尘土。详见 [CHANGELOG-25d.md](CHANGELOG-25d.md)。

## 本地运行

无需构建、后端、CDN 或素材包。安装 Python 3 后，在项目根目录运行：

```bash
python3 -m http.server 8765
```

浏览器打开 <http://127.0.0.1:8765/>。JavaScript 使用原生 ES modules，请通过 HTTP 打开，避免 `file://` 的模块加载限制。

## 操作

| 操作 | 键盘 / 鼠标 |
| --- | --- |
| 行走 | `WASD` / 方向键；点击地面自动寻路 |
| 奔跑 | 行走时按住 `Shift` |
| 调查 / 交互 | 靠近目标后按 `E` / `Space`，或点交互按钮 |
| 前往终端 | 点击场景中的终端，走近后调查 |
| 地图 | `M` |
| 维护手记 / 通讯档案 | `J`，在面板内切换页签 |
| 调查面板：日志 / 配置 | `L` / `C` |
| 调查面板：修复 / 利用 | `F` / `X`，需要先查看两类证据 |
| 关闭面板 | `Esc` |

先找到异常，再查看该终端的**日志**和**配置**，两个证据页都打开过后才能选择**修复**或**利用**，无需滚动读完长文。选择会保存，并改变镇上的场景和最终结局。地图用于查看位置与进度，正常游玩需要亲自走到现场。

游戏时间每现实秒推进约 4 分钟，阅读面板时暂停。午夜折扣门与时间有关；可以走近西街长椅休息至 `00:10`，也可以在夜市调查面板选择“等到次日 00:10”，无需等待完整的昼夜循环。

## 区域与故障

| 区域 | 现场 | 技术原因 |
| --- | --- | --- |
| 西街 | 负金币铺 | `int16` 整数溢出 |
| 西街 | 午夜折扣门 | 跨午夜时只比较 `HH:MM` |
| 中区 | 半开的门 | 竞态 / 缺少互斥 |
| 中区 | 还活着的 Boss | 缓存未失效 |
| 东岸 | 一跳出界 | 米 / 厘米单位混用 |
| 东岸 | 连体分身 | 浅拷贝共享引用 |

完成西街两处维护后开放中区；完成前四处后开放东岸。六处处理完毕后，按选择得到全修复、全利用或混合结局：全修复让系统继续运转，也让维护继续；全利用让旧系统崩塌，通向自由。

## 故事与通讯

新开一局先播放可跳过的接班序言。处理完 **2 处**故障后收到库诺的禁断通讯，处理完 **4 处**后出现“机器正在停止”与委员会的维修记录，处理完 **6 处**后先进入最后交接，再揭晓结局。这些消息是延迟送达的旧档案，不是与仍在地下生活的居民实时通话；关闭消息不会妨碍继续调查。

按 `J` 可在“维护”和“通讯”之间切换，重读已经解锁的档案。各现场的日志与配置一起核对后，会补齐对应通讯中的现场证据；已处理的现场仍可回访。三台服务机的对话也随 0 / 2 / 4 / 6 处进度变化，反复交谈可读到同一阶段的不同记录。故事中的空气、照料与通讯都通过这些档案呈现，不增加第七处修复任务。

三个结局仍严格按六次修复 / 利用的比例判定：**6 次修复**通向机器延续与永久值守，**6 次利用**通向停机与地表自由，其余组合通向局部停机、人与机器重新商量边界的生活。结局不以资源高低另作判定。

## 存档

进度保存在当前浏览器、当前站点的 `localStorage` 中。刷新后可从标题页继续；新游戏会开始新的维护记录。不同浏览器、端口或域名之间不共享存档。清除网站数据也会删除存档。

存档版本升级为 `version: 2`，沿用原存储键，兼容旧版 `version: 1` 记录。维护选择、已查看的证据、时间与位置继续保留；新增故事状态在载入时补齐，已解锁的通讯仍可重读。无法解析的存档不会导致页面崩溃。

## 上传到 itch.io

在项目根目录打包以下运行文件，确保 `index.html` 位于 ZIP 根目录：

```bash
zip -r last-maintainer.zip index.html css js
```

在 itch.io 新建项目，类型选 **HTML**，上传 ZIP，并勾选 **This file will be played in the browser**。建议开启全屏按钮。运行包只需 `index.html`、`css/` 与 `js/`，不需要测试、日志、文档或 `legacy/`。

## 调试与验证

普通地址不开放调试快捷键。开发时打开 <http://127.0.0.1:8765/?debug=1>，可用 `1`–`6` 传送至终端、`T` 快进至下一个午夜，并通过 `window.__maintainer` 检查状态。调试会影响当前存档，建议使用独立浏览器环境。

浏览器冒烟测试使用 Node.js 与 Playwright；它们只用于开发，不进入运行包。测试运行方式和覆盖范围见 [tests/README.md](tests/README.md)。
